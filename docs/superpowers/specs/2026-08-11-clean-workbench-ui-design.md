# 番茄创作发布助手清爽工作台设计

**日期：** 2026-08-11  
**范围：** Tkinter 桌面界面视觉与信息层级升级

## 目标

将当前朴素的 Tkinter 窗口调整为适合反复排程、同步和发布的清爽工作台。用户应能快速识别当前作品、排程范围、当天章节、任务进度与发布结果。

发布自动化、排程规则、章节解析、本地数据结构、番茄后台选择器和错误处理语义均不改变。

## 视觉语言

- 页面背景使用低饱和灰白 `#F4F6F7`，内容表面使用白色。
- 顶栏使用深石墨 `#202A2E`，保留应用图标和名称，形成稳定的窗口锚点。
- 番茄橙 `#E86A3D` 只用于主发布动作、当前作品标记和需要立即处理的状态。
- 青蓝 `#2E7583` 用于选中和同步相关信息；绿色用于已提交，红色用于异常，琥珀色用于超限或部分完成。
- 使用清晰的 8px 间距刻度、4-6px 的小圆角和可见焦点样式。所有状态均有文字，不依赖颜色。

## 页面结构

### 顶栏

- 高度约 64px，左侧为图标和“番茄创作发布助手”。
- 右侧展示任务状态文字、状态点和进度条。空闲时显示“就绪”；同步、发布和失败显示相应状态，但保留已有任务消息和进度机制。

### 小说排程

- 左侧固定宽度作品栏，包含“作品”标题、作品列表和“添加作品”按钮。
- 当前作品使用浅青底、橙色左侧标记和加粗文本；非当前作品保持低对比度但可读。
- 右侧工作区依次呈现：作品名与正文路径、排程设置、发布范围、排程表、当天章节明细和操作栏。
- 排程设置与发布范围使用轻量分隔和小节标题，不堆叠厚重卡片。
- 排程表以清晰表头和更高行距展示日期、章节、字数、状态。状态列使用带文字的颜色标签；每个状态保留 Treeview 标签，便于数据不变时仅改变呈现。
- 当天章节明细显示完整日期时间和当日总字数，表格可纵向滚动，章节标题列优先伸展。
- “发布全部排程”是唯一橙色主按钮；“打开番茄后台”“同步后台状态”等使用次级样式。

### 短故事发布

- 使用与小说页一致的作品侧栏、字段标签、输入框、按钮层级和状态色。
- 正文预览区变为轻量信息面板，显示已识别的正文状态，不新增发布字段或改变发布入口。
- “发布短故事”保持唯一主操作；“保存设置”和“在 Edge 中查看”保持次级样式。

## 组件与数据流

- `PublisherApp._build_window()` 集中定义 ttk 主题、颜色、字体、表格、按钮、Notebook、进度条和状态标签样式。
- `_build_novel_tab()` 与 `_build_short_story_tab()` 仅调整控件容器、栅格、样式名和边距；现有 `StringVar`、事件绑定和回调不变。
- `_refresh_schedule()` 根据现有 `ScheduledDay.status` 与 `over_limit` 为 Treeview 行配置表现标签。`format_schedule_rows()` 的数据格式保持不变。
- `_start_task()`、发布/同步回调和 messagebox 保持现有成功、失败和停止语义；界面只通过现有 `_task_status_var` 和控件禁用状态反映任务生命周期。

## 边界与异常表现

- 没有作品、没有排程或暂停发布时，保持现有空内容逻辑，使用低强调的提示文本。
- 发布过程中按钮继续由现有任务机制禁用，防止重复提交。
- 错误信息仍由现有错误窗口给出章节号、步骤和平台原因，界面美化不得吞掉、改写或自动忽略错误。
- 窗口保持最小尺寸 `980x680`；在默认 `1120x760` 和最小尺寸下，排程和当天明细均可滚动且不遮挡操作按钮。

## 验证

1. 更新 `tests/test_ui.py`，覆盖窗口可构建、排程状态标签和状态文本的表现边界，不使用真实浏览器。
2. 运行 `python -m unittest discover -s tests -v`，确保所有已有发布、排程、短故事回归继续通过。
3. 运行 `build.ps1`，从 `release\\FanqiePublisher\\FanqiePublisher.exe` 启动并人工检查默认尺寸和最小尺寸的布局。
4. 不用真实账号重新提交章节；已完成的发布验收继续作为发布流程回归基线。
