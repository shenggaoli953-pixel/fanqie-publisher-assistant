# 短故事批量导入设计

## 目标

从一个包含多篇短故事的文件夹中一次导入全部正文，保持作者安排的发布顺序，自动填充标题和分类。导入后只需要逐篇补充封面，不改变或发布任何原始正文。

## 来源识别与顺序

- 支持 `.txt` 和 `.md`，但同一编号同时存在两种格式时优先 `.txt`。
- 对类似 `发布顺序/源文件/01_标题.txt` 与 `发布顺序/Markdown/01_标题.md` 的结构，选择 `发布顺序/源文件` 作为唯一导入来源，忽略 Markdown 副本。`发布顺序`、`源文件` 和 `Markdown` 是识别规则，不是固定文件数量。
- 其余普通文件夹将每个可读文本文件视为一篇短故事，按自然排序导入，例如 `2_标题.txt` 在 `10_标题.txt` 前。
- 不递归把同一故事的备份、构建文件或隐藏目录纳入导入。

## 工作台行为

- 短故事页新增“批量导入文件夹”入口。
- 每篇新导入故事保留原始文件路径，标题从 Markdown 首级标题或文件名识别，正文和分类沿用现有解析规则。
- 新故事的封面为空，并在列表和编辑区明确显示“待补充封面”。
- 已存在相同正文路径或同名故事时跳过，避免重复导入；不覆盖用户已经调整过的封面、分类或发布状态。之后向原文件夹新增任意数量的文本文件，再次导入时只补入新增文件。
- 导入结束显示导入、跳过和无法读取的数量；单个文件失败不阻断其余文件。

## 发布边界

- 封面为空的故事不能进入发布提交，会提示先补充封面。
- 批量导入不打开 Edge，不读取番茄后台，也不触发发布。
- 原有单篇添加、目录合并和连续发布功能保持可用。
