# 番茄发布助手可靠性、短故事与桌面界面设计

## 目标

在保留现有作品、排程和发布记录的前提下，把发布流程改造成可观察、可停止、可恢复且以番茄真实结果为准的桌面工具；新增独立的短故事工作流；最终只保留一个稳定桌面入口。

## 已验证问题

- 番茄编辑器在首次正文写入后会异步重建页面，先填的章节号和标题会被清空。
- 章节管理页的“新建章节”入口异步出现，立即读取会误报入口不存在。
- 每次连接都新建标签页会产生同一草稿的多个编辑页面，多个页面可能互相覆盖自动保存内容。
- “发布设置弹窗消失”不能代表成功；成功必须由 `/api/author/publish_article/v0/` 返回 `code == 0`，或回到章节管理页并确认目标章节存在。
- 新作品的空章节列表是正常状态，不得视为加载失败。
- 当前界面在主线程执行整批发布，没有实时进度、停止、日志和失败证据。

## 核心不变量

1. 同一时刻只能有一个发布任务和一个受控番茄工作标签页。
2. 每章开始前先回到章节管理页并同步全分页章节表。
3. 后台已存在同章号时跳过并同步本地状态，不重复提交。
4. 编辑器稳定后先写正文，再写章节号和标题；点“下一步”前再次校验三项内容。
5. 只有接口明确成功，或回章节管理页并找到目标章，才记录为已提交。
6. 提交结果未知时先回后台对账；存在则成功，不存在才允许有限重试。
7. 任一确定失败不弹中间成功通知，整批继续策略由错误类型决定；最终只显示一次汇总。
8. 用户点击停止后，不再开始下一章；正在提交的一章先完成结果判定，避免未知状态。

## 模块边界

- `publisher/browser.py`：浏览器连接、页面会话、小说页面适配器、发布结果判定。
- `publisher/short_story.py`：短故事本地项目解析与配置校验。
- `publisher/short_story_browser.py`：短故事管理页、编辑器、封面、分类和发布适配器。
- `publisher/jobs.py`：后台工作线程、进度事件、停止令牌和批次汇总。
- `publisher/activity_log.py`：轮转日志、失败截图目录和日志导出。
- `publisher/ui.py`：纯界面协调，不直接在 Tk 主线程运行 Playwright。
- 现有 `models.py`、`service.py` 和 JSON 文件继续兼容；新增字段均有默认值。

## 小说发布状态机

`SYNC_MANAGER -> SKIP_OR_OPEN_EDITOR -> WAIT_EDITOR_STABLE -> WRITE_BODY -> WRITE_METADATA -> VERIFY_DRAFT -> NEXT -> HANDLE_WARNINGS -> COMPREHENSIVE_CHECK -> OPEN_SETTINGS -> SUBMIT -> VERIFY_RESPONSE -> RECONCILE_MANAGER`

- 页面加载、入口缺失、编辑器重建属于瞬态问题，可在同一章内有限重试。
- 每日上限、验证码、登录失效、全面检测额度不足属于阻断问题，停止整批并保留剩余章节。
- 提交接口超时或页面中断属于未知结果，必须先回章节表对账，禁止直接再次点击确认发布。

## 短故事模式

短故事不是小说章节的变体。每个短故事项目包含：作品名、正文来源、封面文件、AI声明、主分类、可选附加分类、试读设置和协议确认状态。

- 本地支持单个 `.txt`/`.md` 文件，或文件夹中按自然顺序合并的 `.txt`/`.md` 文件。
- 首次封面上传涉及平台字体与图片协议，软件只检测准备状态并引导用户在浏览器中完成一次，不静默替用户接受新协议。
- 平台“短故事发布事项”在软件中必须显式勾选后才能提交。
- 短故事发布也以平台接口与短故事管理页回读为准。

## 界面

界面采用安静的桌面工作台：左侧作品列表与类型标记，右侧分为排程、短故事设置、运行记录三个页签；底部固定连接状态、任务进度、停止和发布按钮。颜色使用白/浅灰背景、番茄橙作为主要操作色、绿色/红色表达结果，不使用大面积单色或装饰性渐变。

## 数据与迁移

- 继续读取现有 `data/books.json` 和 `data/state/*.json`。
- `BookConfig` 新增 `work_type`，旧数据默认 `novel`。
- 短故事配置单独保存在 `data/short_stories.json`，避免污染小说排程。
- 操作日志保存在 `data/logs/publisher.log`，失败证据保存在 `data/logs/failures/`，均不包含 Cookie、密码或 Token。

## 验收

- 单元测试覆盖状态机、页面竞态、接口结果、未知结果对账、停止和数据迁移。
- 在真实登录后台用当前下一章完成至少一次草稿填写验证和一次完整小说发布验证。
- 空章节新作品可从第1章开始，不因空表中止。
- 短故事至少完成本地解析、真实编辑器填写和发布前校验；没有用户封面/分类或未完成平台协议时不得伪称已完整发布。
- 打包程序可启动，浏览器默认最小化但可从任务栏恢复，桌面只保留一个快捷方式。
